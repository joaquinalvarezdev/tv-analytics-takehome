## 2. WeeklySummary domain logic + tests — `done`

**Owner:** Sonnet agent (isolated git worktree) · **Depends on:** nothing — runs parallel to task 1

Scope: `ReportingCalendar` (anchor → week derivation, local-day bucketing), `ReportingRules` constants,
`WeeklySummaryService` (median baseline, classification, per-location rollup, week-to-date block), and the
PLAN.md test list.

Owned paths: `backend/Relay.Api/Features/WeeklySummary/**`, `backend/Relay.Api.Tests/**`.

Runs in a separate worktree because both tasks build the same MSBuild outputs; the file sets are disjoint and the
orchestrator merges.

Acceptance criteria:
- Zero EF/database/I/O dependency; no new NuGet packages.
- Classification, floor, zero-baseline, `InsufficientHistory`, `NoActivity` semantics exactly as specified.
- Account-level baseline computed from account-wide weekly totals, **not** as a sum of per-location medians.
- **Eligible history = complete local Mon–Sun weeks beginning on or after observation starts** (clarification
  issued mid-implementation; see `ai-log/02-orchestration-dispatch.md` §5). The week containing the account's
  first event counts only when that event's local day is the week's Monday. Regression test required for the
  gate-flip case (first event Sunday 2026-02-01, reported week 2026-02-23 → `InsufficientHistory`,
  `BaselineWeeksUsed == 3`).
- Every PLAN.md test present and passing.

Verify: `cd backend && dotnet build && dotnet test`.
